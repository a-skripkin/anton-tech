# Правила ведения вики

## Зачем

Вики — единственный источник правды о проекте. В код можно посмотреть, но *почему* сделано именно так, что уже проверено и что дальше — только здесь.

## Когда обновлять

| Событие | Что обновить |
| --- | --- |
| Новая задача / фича | Новый файл в `04-logs/`, строка в `changelog.md` |
| Изменение стека или архитектуры | Новый ADR в `05-decisions/` |
| Изменение UI-токенов или компонентов | `03-design/ui-kit.md` |
| Изменение файловой структуры | `01-project/structure.md` |
| Новый термин или сокращение | `00-meta/glossary.md` |

## Соглашения

- Язык документации — русский, код и имена файлов — латиница.
- Файлы и папки: `kebab-case`, даты: `YYYY-MM-DD`.
- Журнал — один файл на день: `04-logs/YYYY-MM-DD.md`. Если день уже начат — дописываем в конец, а не создаём новый файл.
- ADR нумеруются последовательно: `NNNN-kratkoe-nazvanie.md`.
- Ссылки между документами — относительные (`../README.md`).
- В журнале фиксируем факты и результат, а не только намерения.

## Формат записи журнала

1. **Контекст** — что попросили / что сломалось.
2. **Действия** — пронумерованные шаги.
3. **Результат** — что проверено и чем подтверждено.
4. **Следующие шаги** — что осталось.

Шаблон: [06-templates/log-entry.md](../06-templates/log-entry.md).

## Definition of Done

Задача считается закрытой, если:

- [ ] изменения собраны (`npm run build`) и проверены в браузере;
- [ ] добавлена запись в журнал;
- [ ] обновлён `changelog.md`;
- [ ] при необходимости обновлены разделы `01`–`03`.

## Статусы

| Статус | Значение |
| --- | --- |
| `draft` | черновик, не проверено |
| `active` | в работе |
| `done` | выполнено и проверено |
| `blocked` | ждёт решения или внешней зависимости |
