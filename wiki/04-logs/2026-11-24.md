# 2026-11-24 — срочные алерты, пересказ и утренний дайджест

**Статус:** `done`

## Контекст

Пользователь попросил доработать `breach-watch`: проверять инциденты **каждый час**, о «громких» сообщать **сразу**, остальное присылать **утренним дайджестом в 08:00 MSK** (было 09:00). Дополнительно — не выдержки из ленты, а **пересказ** инцидентов по-русски.

## Решения

| Вопрос | Решение |
| --- | --- |
| Где считать «громкий» | ущерб ≥ $10 млн, ≥ 1 млн записей, крупный бренд, признак КИИ / zero-day |
| Расписание | два workflow: `breach-alerts` (каждый час), `breach-daily` (`0 5 * * *` = 08:00 MSK) |
| Дубли между режимами | алерт помечает ссылку `alerted`; утренний дайджест её пропускает |
| Пересказ | цепочка LLM-провайдеров, при отказе — исходная выжимка фида |
| Состояние | `data/seen.json` v3: ссылки + заголовки (одно событие из разных фидов — один раз) |

## Разведка LLM из GitHub Actions

| Эндпоинт | Результат |
| --- | --- |
| `models.github.ai` (GitHub Models, `models: read`) | **200 `OK` text/plain** вместо JSON — эндпоинт перехватывается, даже каталог моделей; не годится |
| `models.inference.ai.azure.com` | домен не резолвится (выведен из эксплуатации) |
| `generativelanguage.googleapis.com` | 403 `PERMISSION_DENIED` (IP датацентра) |
| `translate.googleapis.com` | 429 с IP раннера |
| `text.pollinations.ai/openai` | **работает без ключа**, OpenAI-совместимый; лимит 1 ответ / 45 с на IP (`FREE_LIMIT`, `retryAfter` в теле) |

Вывод: пересказ делается через pollinations с пейсингом; при появлении ключа (`LLM_API_KEY`) первым в цепочке включается OpenAI-совместимый провайдер.

## Действия

1. `scripts/digest.mjs` переписан на два режима: `--mode=alerts` (только критичное, окно 3 ч) и `--mode=daily` (всё остальное, окно 26 ч).
2. Оценка тяжести `assessSeverity()`: суммы в `$`/`€`/₽ (курс `rubPerUsd`), число записей, бренды, маркеры (zero-day, КИИ, «парализован»).
3. Пересказ: `createSummarizer()` — очередь провайдеров, пейсинг (`minIntervalMs`), повтор по `retryAfter` при 402/429, общий бюджет `budgetMs`, отключение упавшего провайдера до конца прогона, защита от не-JSON ответов прокси.
4. Состояние: ссылки + `titles` (нормализованный заголовок → время), `pruneTitles`, `STATE_FILE` для тестовых прогонов.
5. Workflow: отдельные `alerts.yml` и `daily.yml`, общий composite action `save-state`, `concurrency: breach-watch` (прогоны не конфликтуют за состояние), `timeout-minutes: 15`.
6. Обновлены `config/sources.json` (пороги, `dedupeHours`, провайдеры LLM) и `README.md`.

## Ограничения

- Пересказ зависит от бесплатного провайдера: 45 с на ответ, при лимите часть пунктов уйдёт без пересказа. Для стабильности достаточно задать `LLM_API_KEY`.
- Тяжесть оценивается эвристикой по числам в заголовке и описании — возможны пропуски.
- Токен бота передавался в переписке: рекомендуется перевыпустить (`@BotFather` → `/revoke`) и обновить секрет.

## Следующие шаги

1. Задать `LLM_API_KEY` (OpenAI / DeepSeek / OpenRouter) — пересказ станет стабильнее и быстрее.
2. Тонкая настройка порогов: сейчас $10 млн и 1 млн записей.
3. Опционально: тихие часы (не будить ночью мелкими алертами).

- **OrcaRouter**: из этой среды не подтверждён публичный каталог; требуется ручная проверка сайта/доков и наличия провайдера в OpenCode.
